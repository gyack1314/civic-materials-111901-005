# 采集端说明（harvest 包）

面向资料组的限量空间目录采集程序。所有判断只基于 `docs/source-contract.md` 声明的
产品入口（`/boundary`、`/catalog`、`/permit/<code>`）；`/__admin/*` 仅操作员执行
`audit` 子命令时读取，采集主流程不调用。

## 1. 覆盖语义（为什么结论可解释）

- **收集范围**是市域多边形与地块**真实几何的相交**（含边界接触），既不是外接矩形，
  也不是「设施中心点落入市域」。每个在范围内的地块保存与市域的相交足迹（`coverage.geojson`
  中的 `parcel_intersection`）。
- 一次目录查询只有在响应 **`truncated=false`** 时才构成覆盖「瓦片」：它证明该矩形+
  该类别通道已被完整观察。**空列表的未截断响应同等有效**，证明该范围没有该类设施，
  空结果查询同样留痕、同样计入覆盖。
- `truncated=true` 只说明「还有结果」，**不产生覆盖**，仅保留为查询足迹。
- 覆盖面积 = 未截断查询矩形的并集，再**裁剪到市域多边形**；市域带缺口时，界外矩形
  部分不计入覆盖，也不会被当成已观察。
- 报告按来源声明的每个类别（solar/heat/storage）分别给出覆盖率与是否完整，
  而不是只看去重后的设施总数。

## 2. 截断的处置顺序（不会无限分割，也不会把缺口当空区）

1. **类别升级**：全量查询截断时，改用契约允许的 `category` 参数逐类查询。类别互斥，
   每个类别单独取得未截断响应即单独完成覆盖（同址密集设施靠这一步分离，而非切碎矩形）。
2. **空间二分**：某类别在矩形内仍截断时，矩形沿长边二等分递归；与市域不相交的
   子矩形直接跳过（本就不属于收集范围）。
3. **兜底为缺口**：矩形跨度已不大于最小分割跨度（根矩形最长边 × 1e-7）、达到最大
   深度 32，或单次运行任务预算（默认 2000）耗尽仍截断的范围，登记为 **gap**：
   记录矩形、类别通道与原因，报告中明确列为「来源限制下无法确认的区域」。
   缺口不是空区，也不会被静默丢弃；重跑时开放缺口会重新入队继续推进。

## 3. 地块、设施与许可的身份关系

- `parcel` 是地块主键、`facility` 是设施主键，含义不同。一个设施的所有相交地块
  都属于它的覆盖证明（如 F-A 由 P-A1、P-A2 共同组成，不会被误拆成两个项目）。
- 每次观测保留 `parcel × query` 多对多溯源链：`harvest provenance --parcel <id>`
  可查该地块来自哪次运行、哪个 URL、什么轴序、返回顺序，以及是否来自截断响应。
- **许可按设施登记一次**。多个地块共同引用同一许可地址时，`permits` 表只有一条
  设施记录；下载 URL、sha256、尝试次数与状态均挂在设施上。
- 许可 PDF 必须能解析出页内文字声明的 `facility=` 且与目录一致才采信：
  - 一致 → `permits/<facility>.pdf`，状态 `verified`，记录验证时的边界分代；
  - 不一致 / 无身份声明 / 非 PDF / 无法解析 → 原件放入 `quarantine/` 隔离留证，
    状态 `rejected`，记录页内实际声明的代码与原因，**绝不拿可打开的 PDF 充数**。
- 一次采集暂缺许可不影响任何空间观测；之后重跑 `permits` 补收成功，设施转为
  资料齐备，且**不改动** `catalog_queries` 与 `scope_eval`（范围证明不变）。
- 边界换代会使旧分代的 `verified` 自动失效（转 `pending` 重新核实），已下载文件
  保留留档但不再被采信。

## 4. 坐标版本与分代

- `--api xy|yx` 选择接口版本；无论哪个版本，**bbox 输入始终按经纬度**。
- 响应的 `axis`（`lon,lat` / `lat,lon`）与 `crs` 随原文落库；几何在入库时按 `axis`
  声明归一化为经纬度顺序，未知 axis 直接报错而不是猜测。
- 每次响应的 `revision` 与边界分代绑定。采集中途发现 revision 变化会中止当次运行
  并保留现场，要求以新边界重新采集；旧代查询永久留档，但只参与旧代的覆盖结论。

## 5. 命令

在项目根目录执行（采集库与原件写在 `--out` 目录，可随时终止后重跑续收）：

```bash
python -m harvest run     --base http://127.0.0.1:8765 --out ./out          # 空间采集/续跑
python -m harvest permits --base http://127.0.0.1:8765 --out ./out          # 许可下载、核对、补收
python -m harvest report  --out ./out                                       # 生成交付物
python -m harvest provenance --parcel P-A2 --out ./out                      # 地块级溯源
python -m harvest audit   --base http://127.0.0.1:8765 --out ./out          # 操作员：来源足迹对账
```

`run` 可反复执行：同一矩形+通道在同一分代下已有成功响应时直接复用，不重复请求来源；
换界后自动按新分代重新建立覆盖。`permits` 默认对 `pending` 与 `rejected` 都重试
（来源修订后被拒许可可能恢复身份），已验证的当前分代原件不重复下载；
`--only-pending` 可限制为只补暂缺项。

## 6. 交付物（`--out` 目录）

| 文件 | 内容 |
| --- | --- |
| `harvest.db` | SQLite 全量留痕：边界分代、每次查询（含截断/空结果原文）、地块观测与溯源、市域归属、许可状态、缺口、运行记录 |
| `report.json` | 机器可读结论：分类别覆盖率、缺口、设施-地块归属、许可状态、界外观测、历次运行 |
| `report.md` | 资料员可读中文报告：明确已完整观察的空间与仍无法确认的缺口 |
| `coverage.geojson` | 边界、各通道覆盖几何、缺口几何、地块×市域相交足迹 |
| `permits/*.pdf` | 身份核对通过的许可原件（文件名=设施代码） |
| `quarantine/*.pdf` | 身份不符或无法解析的隔离件，文件名含页内声明的实际设施代码 |
| `audit.json` | 本地查询与来源 `/__admin/log` 实际足迹的逐条对账结果 |
